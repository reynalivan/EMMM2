# Configured startup audit — 2026-10-09

## Main findings

### P1: Same-game activation rebuilds the verified startup watcher

Successful bootstrap promotes its inactive watcher to the active slot and
verifies authority before completing recovery (`bootstrap.rs:319`). Settings
hydration waits for that completion. The frontend's initial active ID is still
null, so `initStore` submits `set_active_game` (`gameSlice.ts:237`).

Activation checks only inactive watcher readiness (`settings_cmds.rs:379`). The
inactive entry has already been consumed by handoff, so activation resets the
recovery gate, invalidates the active session and drops its watcher (386–391).
With no inactive watcher to adopt, lifecycle builds a fresh watcher/cache and
requests a full `GameSwitched` reconcile. This remains in the current code even
with the backfill marker and once-only frontend initialization.

Recommended fix: reuse the current same-game watcher before invalidation, using
the existing configured-root/runtime coverage, physical identity, clean authority,
repair and pending-journal checks. Publish the new activation generation, settings
acknowledgement and runtime effects through the existing verified outcome flow.
Same-ID or stored Ready shortcuts are insufficient.

### P1: File-ID cache warming adds an unreported full-tree walk

`watcher/mod.rs:523` calls recursive `Debouncer::watch`. In the installed dependency
`notify-debouncer-full 0.7.0`, watch registers the OS watcher and then fills its
cache. Windows `RecommendedCache` is `FileIdMap`; `add_path` uses a recursive
`WalkDir` and reads native IDs for every file/directory, following links.

Bootstrap does this before calling the timed reconcile. It also holds the
activation guard during installation. Consequently `disk reconcile total_ms`
omits this cost, while settings hydration and activation can wait behind it.

A read-only native harness on the actual configured large library measured:

| Measurement                                    |      Sample 1 |      Sample 2 |
| ---------------------------------------------- | ------------: | ------------: |
| Native registration with diagnostic NoCache    |      0.867 ms |      0.388 ms |
| Production watcher registration with FileIdMap | 28,898.920 ms | 26,086.634 ms |

The diagnostic control does not provide production rename proofs. It is not a
proposed safe replacement. First avoid duplicate installation; then measure and
design a bounded/selective identity cache while preserving rename stitching,
replacement detection, lost-event recovery and watcher coverage.

Harness: `src-tauri/tests/startup_watcher_audit.rs`, ignored by default. Set
`EMMM_AUDIT_MODS_ROOT` to the configured absolute root and run from `src-tauri`:

```powershell
rtk proxy cargo test --test startup_watcher_audit -- --ignored --nocapture
```

No filesystem/database writes or game mutation are performed by the harness.

### Installed application still contains the legacy marker bug

The running process uses the installed executable, not a workspace build.
Its binary contains both legacy `SELECT ... FROM app_meta` and `INSERT ... INTO
app_meta` query strings. The live database has no `unicode_key_version` row.
Thus the earlier source fix is not active in that application. Do not interpret
its restart timings as a measurement of the repaired source.

The latest real log records a 16,552 ms `StartupBoot` reconcile on 30,290
directories, with 8,617 ms classification and 4,608 ms DB projection. It loads
444 object rows and 12,729 mod rows for a 148-object/4,243-mod projection (3×).
A later full `GameSwitched` reconcile takes 5,360 ms. These timings are different
stages/samples; they must not be added into a claimed end-to-end startup time.

### P2: Initial backfill stages unchanged objects and reloads indexes

Object backfill derives keys against the Mods root (`unicode_keys.rs:91`), while
normal object writers and disk snapshots use relative keys. Identity preparation
therefore stages unchanged objects after backfill. It loads the entire index
initially, again after object staging and again before applying rows. When only
objects stage, the latter two loads read identical rows.

The durable marker makes the key repair one-time. Align object backfill with the
normal writer and reuse the post-object index when no mod staging changes it.
Test true identity swaps as well as unchanged post-backfill reconciliation.
No mod-size cache miss is established; mod keys intentionally use their own
namespace and size-scan keys are recomputed from stored folder paths.

### Optional staging cleanup can block setup, but is absent here

Startup synchronously loops over all historical terminal import batches and
recursively cleans staging before setup returns. That can grow with history.
The inspected database has zero import batches and no staging root, so this is
not an evidenced contributor to the current user's delay.
